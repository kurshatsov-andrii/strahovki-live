# База даних, калькулятор тарифів і адмінка

## 1. Lovable Cloud (база даних + вхід)
Вмикаємо вбудований бекенд. Таблиці:

- `tariffs` — тарифи для розрахунку: продукт (auto / green_card / travel / sport),
  назва страхової компанії, базова ціна, набір коефіцієнтів (регіон, тип авто,
  зона країн, вік, спорт-ризик), активність, сортування.
- `leads` — заявки з форм і калькулятора: ім'я, телефон, email, продукт,
  параметри розрахунку, розрахована ціна, коментар, статус (нова / в роботі /
  оформлена / відмова), дата.
- `site_settings` — контакти, телефони, месенджери, графік роботи (щоб
  редагувати з адмінки без правок коду).
- `user_roles` + роль `admin` — доступ до адмінки лише для адміністраторів.

Дані читаються публічно тільки для тарифів і налаштувань; заявки бачить лише
адмін. Початкові тарифи заливаються одразу разом зі структурою.

## 2. Калькулятор тарифів
Компонент калькулятора на кожній продуктовій сторінці, з полями під продукт:

- Автоцивілка: регіон реєстрації, тип ТЗ, стаж/вік, строк (1/6/12 міс).
- Зелена карта: тип ТЗ, зона (Європа / Молдова), строк (15 днів – 12 міс).
- Туристичне: країна/зона, кількість днів, вік, сума покриття.
- Спортивне: вид спорту (аматор / професійний / екстрим), строк, сума покриття.

Розрахунок робиться на сервері за тарифами з бази — видає список пропозицій
страхових компаній з цінами, від дешевшої до дорожчої. Кнопка «Оформити»
відкриває форму заявки, яка зберігає лід із обраним тарифом і ціною.
Форма контактів теж починає зберігати заявки в базу.

## 3. Адмінка `/admin`
Закритий розділ (вхід через email + пароль, доступ лише ролі `admin`):

- Дашборд: кількість заявок за період, суми, розподіл за продуктами.
- Заявки: таблиця з фільтрами за продуктом і статусом, деталі заявки,
  зміна статусу, нотатки, експорт у CSV.
- Тарифи: створення / редагування / вимкнення тарифів і коефіцієнтів.
- Налаштування сайту: телефони, email, месенджери, графік — одразу
  відображаються в шапці й футері.

Сторінка `/auth` для входу адміністратора; перший адмін призначається вручну
після реєстрації.

## Технічні деталі
- Дані читаються серверними функціями TanStack Start (`createServerFn`);
  публічні читання тарифів — через анонімні SELECT-політики, заявки й
  адмін-операції — через авторизовані функції з перевіркою ролі.
- RLS увімкнено на всіх таблицях; ролі зберігаються в окремій таблиці
  `user_roles` (не в профілі) для безпеки.
- Адмін-маршрути під `_authenticated`, валідація форм через zod.
- Дизайн адмінки — у тій самій зеленій палітрі, компоненти shadcn.
